# Libreto de Exposición: Los 6 Scripts de Operaciones (`scripts/`)

> **Cómo exponerlo:** Léelo o dilo con fluidez mientras muestras la carpeta `scripts/` en tu editor de código. Las palabras en **negrita** son para proyectar firmeza técnica ante el jurado.

### Libreto de Exposición Continua

"Pasando ahora a la carpeta **`scripts/`**, aquí modularizamos toda la lógica operativa del pipeline en **6 scripts Bash desacoplados**, todos configurados con la directiva **`set -e`** para garantizar que ante cualquier fallo el script se detenga de inmediato, evitando que el pipeline continúe a ciegas:

Primero, en la Etapa 2 del pipeline, antes de compilar o tocar AWS, ejecutamos **[`validate-params.sh`](file:///mnt/c/Users/elvis.chafloque_prag/Documents/Prueba_tecnica/scripts/validate-params.sh)**. Este script aplica el principio **Shift-Left**: itera sobre `dev.json`, `staging.json` y `prod.json` y los valida con la herramienta **`check-jsonschema`** contra nuestro contrato en **`schema.json`**. Con esto garantizamos de forma automática que variables críticas como retenciones de logs, niveles de auditoría y orígenes CORS cumplan estrictamente el contrato tipado, cancelando el pipeline en apenas tres segundos ante cualquier inconsistencia humana.

Segundo, en las Etapas 5 y 7, inmediatamente después de que CloudFormation aprovisiona la infraestructura, ejecutamos **[`deploy-frontend.sh`](file:///mnt/c/Users/elvis.chafloque_prag/Documents/Prueba_tecnica/scripts/deploy-frontend.sh)**. Este script resuelve el problema de caché en aplicaciones web de una sola página: consulta dinámicamente los nombres de recursos en CloudFormation; sincroniza los archivos `.js` y `.css` versionados con **caché inmutable de un año** en S3; sube el **`index.html` con política estricta de `no-cache`**; y finalmente ejecuta una **invalidación selectiva en CloudFront sobre `/index.html`**. Con esto logramos despliegues instantáneos con cero tiempo de indisponibilidad y aseguramos que el cliente siempre vea la última versión sin requerir refrescos forzados en su navegador.

Tercero, ejecutamos **[`smoke-test.sh`](file:///mnt/c/Users/elvis.chafloque_prag/Documents/Prueba_tecnica/scripts/smoke-test.sh)** para realizar la **verificación post-despliegue en vivo**. Como las pruebas unitarias corren con datos simulados y no detectan errores de permisos en IAM ni fallas de red, este script ejecuta en solo tres segundos cuatro pruebas reales con **`curl --fail`**: crea un siniestro en DynamoDB con `POST /claims`, consulta el registro con `GET`, actualiza su estado con `PATCH`, y genera el reporte PDF en S3 con `POST /documents/report`. Si cualquiera de los servicios falla o devuelve un error HTTP, el pipeline se aborta de inmediato.

Cuarto, en el bloque `post` del pipeline, se dispara **[`dora-metrics.sh`](file:///mnt/c/Users/elvis.chafloque_prag/Documents/Prueba_tecnica/scripts/dora-metrics.sh)**. Este script calcula el **Lead Time real en minutos**, restando la hora actual menos el timestamp del último commit en Git mediante `git log -1 --format=%ct`. Luego, publica las **cuatro métricas DORA** —Frecuencia de Despliegue, Lead Time, Tasa de Fallos y MTTR— directamente en **Amazon CloudWatch** con `aws cloudwatch put-metric-data`, consolidando en el mismo tablero operativo la salud del código y la velocidad del equipo sin pagar licencias de herramientas SaaS adicionales.

Quinto, como valor agregado de innovación y gobierno, implementamos **[`ai-devops-assistant.sh`](file:///mnt/c/Users/elvis.chafloque_prag/Documents/Prueba_tecnica/scripts/ai-devops-assistant.sh)** integrado de forma nativa con **Amazon Bedrock** utilizando el modelo **Nova Micro**. Este script opera en dos modos: en modo **`triage`**, resume los escaneos de seguridad de Gitleaks, Semgrep, npm audit y Checkov en un dictamen ejecutivo de Markdown para el aprobador del pase a Producción; y en modo **`failure`**, si una etapa o un despliegue Canary falla, diagnostica la causa raíz y entrega el comando exacto para remediar el incidente, contando además con un mecanismo de respaldo automático.

Y sexto, creamos **[`teardown.sh`](file:///mnt/c/Users/elvis.chafloque_prag/Documents/Prueba_tecnica/scripts/teardown.sh)**, un script de limpieza total que vacía automáticamente los buckets de S3 y elimina todos los stacks de CloudFormation con `delete-stack` al finalizar la evaluación, garantizando que no queden recursos huérfanos y manteniendo la cuenta en **costo cero absoluto**."
